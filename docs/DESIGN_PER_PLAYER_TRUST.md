# 개인 신뢰 (2026-10-08 설계, 2026-10-09 다시 정리, 아직 구현 안 함)

## 1. 목적과 가정

**가정 (2026-10-09 사용자)**: 한 서버에서 같이 하는 플레이어들은 서로 경쟁하지 않고, 무리의 일(이야기·위기 등)은 의견을 모아 함께 정한다.
**목적**: 신뢰도로 얻는 혜택(거래·특기 등)은 **각자 노력한 만큼** 얻는다. 누가 애써 올린 신뢰도를 아무것도 안 한 사람이 그대로 누리지 않게.

그래서 일을 성격으로 완전히 나눈다.

- **무리의 일 → 집단 신뢰만** 움직인다. 무리가 합의해서 하는 일이라 누가 손을 보탰는지 나누지 않는다.
- **개인의 일 → 그 사람의 개인 신뢰만** 움직인다.
- **혜택은 개인 신뢰로만** 판정한다.

(버린 안: "캐릭터별 신뢰도 + 개인 주파수"는 NPC 태도·대화 기록·AI·디렉터까지 모두 나눠야 해 너무 크다. 혜택에 min(집단, 개인)은
동료의 실수까지 떠안는다. 무리의 일을 참여자·빠진 사람으로 나눠 개인 신뢰에 반영하는 안(2026-10-08)은 경쟁·방해를 막는 장치였는데,
위 가정에서는 필요 없어 뺐다.)

## 2. 두 가지 신뢰

| | 집단 신뢰 (지금의 신뢰도) | 개인 신뢰 (새로) |
|---|---|---|
| **뜻** | NPC 가 이 서버의 플레이어 무리를 얼마나 믿는가 | NPC 가 이 캐릭터 한 사람을 얼마나 믿는가 |
| **저장** | `Radio.channel(fid).trust` (그대로) | `ch.personal[캐릭터 키]` 0~100 (키 = `Store.playerKey`) |
| **움직이는 일** | 무리의 일만 (5-1절) | 개인의 일만 (5-2절) |
| **쓰는 곳** | 이야기·곁가지 조건, 위기, 카운티 회의, 다른 NPC 이야기, 후임, 서버 전체 사건에서 청할 NPC 고르기(구조 신호 등, 5-3절), 복구 작전 NPC 지원 구간, AI 곁가지 등급, AI 의 무리에 대한 태도, 새 캐릭터 소개 몫, 인물 탭 "신뢰 20/40/60/80 처음 넘음" | 모든 혜택 (4절), 개인별 부탁의 NPC 고르기·등급 상한, 협박, AI 의 이 사람에 대한 태도 |

- 개인 신뢰의 시작값 = NPC 처음 값(샌드박스 `TrustStart` 반영) + `(그 순간의 집단 신뢰 - NPC 처음 값) x 소개 비율`(0 미만이면 0).
  처음 연락하는 순간 정해진다: 그 NPC 와 무전하거나, 그 NPC 의 일을 맡거나, **그 NPC 에게서 개인별 부탁을 받거나**.
  무리가 쌓은 신뢰가 새 사람에게 조금 이어지는 유일한 통로.
- 죽고 새 캐릭터를 만들면 개인 신뢰도 새로 (소개 몫은 받음). 죽은 캐릭터의 기록은 `ch.personal`에서 지운다(세이브가 커지지 않게,
  `Legacy` 의 죽음 기록과 같은 때).

## 3. 모드와 샌드박스 옵션 (NPC 페이지)

| 옵션 | 값 | 기본 |
|---|---|---|
| `TrustBenefits` 신뢰도 혜택 | 1 서버 공유 (지금 구조: 신뢰 하나) / 2 개인 신뢰 | 1 |
| `TrustIntro` 소개 비율 (2일 때) | 0~100% | 25% |
| `HelperTrustShare` 개인 부탁을 도운 사람이 받는 몫 (2일 때) | 받은 사람이 얻는 신뢰의 0~1배 (5-3절) | 0.5 |
| `PersonalAskMinDays` / `PersonalAskMaxDays` 개인별 부탁 간격 (2일 때) | 일 (5-3절, 최대가 최소보다 작으면 최소로) | 2 / 5 |
| `TrustFadeDays` / `TrustFadeEvery` / `ChatTrustMax` | 6절 속도 조정 | 14 / 3 / 40 |

- **싱글은 늘 지금 구조** (신뢰 하나가 모든 일로 움직이고 혜택도 그 값). 캐릭터가 하나라 나눌 이유가 없다. `TrustBenefits`는 멀티에서만 본다.
- 멀티 + 1(공유)도 지금 구조. 아래 4~5절은 **멀티 + 2(개인)** 의 규칙.
- 예전 세이브에서 2로 켜면: 이미 있는 캐릭터의 개인 신뢰 = 그때의 집단 신뢰 (기록이 없으므로 손해 보지 않게).
- 2에서 1로 되돌리면: 집단 신뢰 = max(집단 신뢰, 개인 신뢰가 있는 살아 있는 캐릭터들의 평균). 개인 모드의 집단 신뢰는 무리의 일로만
  올라 낮으므로, 그대로 두면 혜택이 갑자기 줄어든다. 개인 기록은 지우지 않고 남겨 두어 다시 2로 켜면 이어 쓴다.
  모드가 바뀐 것은 `d.trustMode`에 기억해 두고 서버 시작·`EveryHours`에서 확인한다.
- 2일 때 특기 대기 범위(`SpecialtyScope_<npc>`)가 1(서버 전체)이면 3(둘 다: 쓴 사람은 그 NPC 대기 일수, 다른 사람은 1일)으로 본다.
  혜택을 개인으로 나눴는데 남이 쓰면 나도 일주일 못 쓰는 일이 없게. 2·3 으로 정해 둔 NPC 는 그대로.

## 4. 혜택 = 개인 신뢰 (`Trust.personal(fid, key)`)

| 혜택 | 지금 | 판정하는 사람 |
|---|---|---|
| 거래 등급 한도·값·공짜 확률·흥정 하한 | `Trade.context`·`ask`·`options`·`offerContext` | 청한 사람 (1:1 무전에서 말한 사람, 버튼 누른 사람) |
| 공용 주파수 시장 제안 | `Trade.marketContext`·`marketOffers` | 말한 사람 |
| 특기 구간·조건 (40/60/80) | `Specialty.status`·`request`·`tier` | 요청한 사람 |
| 외상(60)·빚(40) 자격, 일거리 청하기 등급 | `Work.check`·`volunteer` | 청한 사람 |
| 선물 편지(70), 친구 선물(60), 명절 세뱃돈·작은 보급 | `Letters.attach`·`Director` friend·`Holiday` | 받는 사람 (기준을 넘는 사람에게만) |
| A-Life 자동 지원(70) | `ALife` auto | 위험한 그 사람 |
| 디렉터 일반 부탁 등급 상한 (0~19 → 2 … 60+ → 5) | `Director.tierCap` | 부탁을 받는 사람 |

- **거래는 (NPC, 사람)마다 하나**: 지금은 NPC 마다 열린 거래가 서버 전체에 하나(`Quests.openTrade(fid)`)라 남의 제안이 내 거래를 막는다.
  2일 때는 사람마다 하나씩. 재고는 NPC 공유라 먼저 사는 사람이 가져간다.
- **협박**: 그 NPC 에 대한 개인 신뢰가 10 이하인 접속자가 있으면 열리고, 대상은 그중 가장 낮은 사람(같으면 가장 최근에 떨어뜨린 사람).
  집단 신뢰는 무리의 일로만 움직여 시작값(빅 5·휘태커 10)에 오래 머물기 때문에 집단 기준이면 협박이 거의 늘 열려 있게 된다.
- **혜택이 아닌 것**: 복구 작전 중 NPC 지원(`Specialty.assist`)의 구간은 무리의 일이라 **집단 신뢰**로 정한다. 빅 교역소 암시장은
  지금처럼 신뢰와 무관.
- 거절 줄·오류: "신뢰 부족: 3등급 의약품은 40부터 (당신 35)".

## 5. 신뢰가 바뀌는 일 (멀티 + 개인 모드)

값(완료 +등급, 거절·무응답·실패 감점표, 진행 단계 배율, 주간 상한 등)은 지금과 같다. 바뀌는 것은 **어느 신뢰에 들어가느냐**뿐.
`Trust.apply(fid, delta, reason, questId, byKey, src)`가 이유와 "누가 했는지"를 이미 받으므로 이유로 가른다.

### 5-1. 무리의 일 → 집단 신뢰만

| 이벤트 | 집단 신뢰 |
|---|---|
| 큰 이야기·곁가지·AI 곁가지 부탁 완료 / 수락 / 거절 / 무응답 / 실패 | 지금 표 그대로 (+등급 / 0 / 감점 / 감점 / 감점) |
| 위기: 고른 NPC / 함께 바라던 NPC / 외면당한 NPC / 무응답 | +2 / +1 / -2 / -1 |
| 위기 후속 부탁 | 이야기 부탁과 같음 |
| 큰 사건 결말 (열병 닥 +3) | +3 |
| 명절 모금 완료 (주관 NPC) | +1 |
| **장기 프로젝트 완성** (그 NPC) | **+15** (`Projects.GROUP_TRUST`, 개인 모드만. 6절: 이야기만으로는 회의 조건에 못 미쳐서) |
| 무리의 일에서 번진 관계 파급 (3등급 이상 이야기 부탁·위기 선택 → 다른 NPC) | ±1 |

- 거절·무응답은 무리가 합의한 결정으로 본다. 지금처럼 누가 거절하든 바로 닫힌다.
- **무리의 일로는 아무의 개인 신뢰도 오르거나 내리지 않는다.** 손을 보탠 사람의 몫은 부탁 보상 보급과 이야기 진행.
  다만 손을 보탠 것은 그 NPC 를 "상대한 날"로 쳐서 개인 신뢰가 식지 않게 한다 (6절).
- 무리의 일에서 번진 관계 파급도 집단 신뢰만 (다른 NPC 의 집단 신뢰 ±1).
- 복구 작전·카운티 회의는 지금처럼 신뢰도가 바뀌지 않는다 (NPC 형편·관계만).
- 신뢰도가 아닌 간접 영향은 남는다: 무리의 일 실패로 NPC 형편이 나빠지면 거래(자원 20 미만 품목은 안 팖)·특기(핵심 자원 20 이상)가
  모두에게 막힐 수 있고, 이야기 최악 결말로 NPC 가 떠나면 후임에게는 모두의 개인 신뢰가 처음부터다. 무리가 함께 겪는 결과로 둔다.

### 5-2. 개인의 일 → 그 사람의 개인 신뢰만

| 이벤트 | 개인 신뢰가 바뀌는 사람 |
|---|---|
| 개인별 부탁 (물건·소탕·찾아오기·아는 얼굴, 5-3절) 완료 | 받은 사람 +등급, 도운 사람 x `HelperTrustShare`(0.5) |
| 　〃 거절·무응답·실패 | 받은 사람만 감점 (도운 사람은 감점 없음) |
| 서버 전체 부탁 (급한 부탁·겨울 난방) | 수락한 사람 (완료 때 도운 사람 x `HelperTrustShare`), 무응답은 디렉터가 고른 사람 |
| 빚 독촉 부탁 거절·실패 (떼먹기) | 빚진 사람 (큰 감점, 30까지) |
| 협박에 응함 | 낸 사람 +1 |
| 선물·구조 신호 보급 가져감 / 놓침 | 받은 사람 +1 / -1 |
| 거래 완료 / 실패, 외상 떼먹기 | 거래한 사람 (완료는 주 +5까지, 사람마다) |
| 거래 요청 과다 (7일에 3번째부터 -1) | 청한 사람 (횟수도 사람마다) |
| 무전 대화 하루 +1 (40 미만일 때) / 모욕 -1 | 말한 사람 (하루 +1 도 사람마다) |
| 물자·프로젝트 지원 (+1/+2/+3) | 보낸 사람 (3일 지원 통도 사람마다: 자원 +40·프로젝트 100점 한도와 신뢰 단계 모두, 2026-10-09 사용자 결정 (나)) |
| 일거리 청하기 완료 / 실패 | 맡은 사람 (+등급x2 / -등급) |
| 보상 사양 | 사양한 사람 (+등급) |
| 개인의 일에서 번진 관계 파급 (다른 NPC ±1) | 그 일을 한 사람, **이미 아는 NPC 에게만** (모르는 NPC 의 개인 신뢰를 새로 만들지 않는다) |
| 레이 보급 특기 (받은 NPC +1) | 특기를 요청한 사람 |

### 5-3. 개인별 부탁 (디렉터 일반 부탁을 사람마다)

- **지금**: 디렉터가 하루 두 번(08:00·20:00) 사건 하나를 고르고, 일반 부탁이면 접속자 중 한 사람 앞으로 낸다
  (`Director.events.npc_request` → `Quests.propose(entry.player, ...)`: 거리·NPC 무전도 그 사람 기준). 퀘스트는 모두에게 보이고 누구든
  수락할 수 있으며 수락한 사람이 `q.target`. 관문은 NPC 마다 4일+, 서버 전체로 이틀에 하나라 4명이면 한 사람 차례가 8일에 한 번꼴.
- **개인 모드: 사람마다 따로 오는 부탁** (`Director.personalAsks`, 디렉터 사건에서 떼어 냄). 게임 내 1시간마다 접속자마다 확인한다.
  - 간격: 그 사람의 마지막 개인별 부탁 뒤 `PersonalAskMinDays`~`MaxDays`(2~5일, 사람마다 굴림)가 지났고 그 사람에게 열린 개인별 부탁이 없으면 하나.
    새 캐릭터는 처음 2일 없음. 인원이 늘어도 한 사람이 받는 양은 같다.
  - 청하는 NPC: 그 사람의 개인 신뢰 가중치(+10). 같은 NPC 가 같은 사람에게는 4일 간격, 떠난 NPC 제외.
  - 종류: 물건 60%·소탕 40% (지금 비율), 찾아오기, 아는 얼굴의 좀비(그 사람의 개인 신뢰 30 이상). 등급 상한 = 그 사람의 개인 신뢰와 진행 단계.
  - **받은 사람만 수락·거절한다** (`q.addressed`). 다른 사람은 물건을 나눠 내거나 같이 소탕하며 도울 수 있고, 도운 사람은 `q.helpers`.
  - 결과: 완료하면 받은 사람 +등급, 도운 사람은 그 `HelperTrustShare`배(기본 0.5, 반올림, 0 이 되면 없음).
    거절·무응답·실패 감점은 받은 사람만. 보상 보급은 받은 사람 근처.
  - **답할 시간(12시간)은 받은 사람이 접속해 있는 동안만 센다**. 접속을 끊은 채 기한이 오면 감점 없이 조용히 닫는다(`declined` +
    `q.lapsed`). 수락한 뒤의 기한(물건·소탕)은 지금처럼 게임 시간 그대로 (맡은 일이라서).
  - AI: 부탁 무전(`mode = "request"`)에도 받은 사람의 개인 신뢰·아는 정도(7절)를 넘겨, 처음 보는 사람과 오래 안 사람에게 다르게 청한다.
  - **큰 이야기를 막지 않는다**: 지금은 그 NPC 에게 열린 물건·소탕·아는 얼굴 부탁이 있으면 이야기 부탁이 나오지 않는다
    (`Social.openQuestFor`). 개인별 부탁(`q.addressed`)은 이 검사에서 뺀다. 안 그러면 사람이 많을수록 이야기가 계속 밀린다.
- **디렉터 사건이 어디로 가나 (개인 모드)**

  | 사건 | 어디로 | 신뢰 |
  |---|---|---|
  | 일반 부탁(물건·소탕), 찾아오기, 아는 얼굴의 좀비 | 개인별 부탁 예약 (위) | 받은 사람 (+ 도운 사람 몫) |
  | 친구 선물 보급 | 사람마다: 개인 신뢰 60 이상인 NPC 가 그 사람에게, 사람마다 3일 간격 | 받은 사람 (가져가면 +1 / 놓치면 -1) |
  | 구조 신호 보급, 디렉터 보급 | 지금 디렉터 사건 그대로 (대상은 디렉터가 고름, 구조 신호를 전하는 NPC 는 집단 신뢰 가중치) | 받은 사람 (+1 / -1) |
  | 협박 | 지금 디렉터 사건 (위협 세력마다 5일 간격), 열림·대상은 개인 신뢰 (4절) | 응한 사람 +1 |
  | 급한 부탁 | 지금처럼 서버 하루 하나 (NPC 형편이 정함, 대상은 디렉터가 고름) | 수락한 사람 (+ 도운 사람 몫), 무응답은 고른 사람 |
  | 겨울 난방 부탁 | 지금처럼 (World) | 급한 부탁과 같음 |
  | 폭풍·헬기·호드 유도·조용한 하루 | 그대로 | 없음 |

  NPC 별 관문(4일)·서버 전체 이틀에 하나(`Director.openAskers`)는 구조 신호·협박에만 남는다.
- AI 무전 호출이 인원수만큼 늘어난다. 브릿지가 없으면 준비된 대사로 나간다.
- 싱글·공유 모드는 지금처럼 디렉터 사건으로 (서버 전체 이틀에 하나).

## 6. 속도 조정 (2026-10-08 점검)

점검: 혼자 열심히 하면 NPC 하나에서 주 +20~40 (대화 +7·물자 지원 +7·거래 +5·일거리 +4~20·부탁·이야기 몇)이라 시작 0 인 행크도
3주 남짓에 80, 1년 게임에서 첫 달에 끝난다. 반대로 안 만나도 떨어지지 않는다. 사용자 결정으로 아래 둘만 적용 (주간 합산 상한은 안 함).
싱글·공유 모드는 신뢰 하나에, 개인 모드는 개인 신뢰에만 적용한다.

1. **관계는 가꾸지 않으면 식는다**: `TrustFadeDays`(14)일 동안 그 NPC 와 아무 일(무전 대화·부탁·거래·물자 지원·일거리·특기)이 없으면
   `TrustFadeEvery`(3)일마다 -1. "NPC 처음 값 + 20" 아래로는 내려가지 않는다.
   개인 신뢰는 그 캐릭터가 접속한 날만 "상대하지 않은 날"로 센다(`ch.personalIdle[키]`). 싱글·공유 모드는 누군가 접속한 날 중
   아무도 그 NPC 를 상대하지 않은 날을 센다.
   **그 NPC 의 무리의 일(이야기·곁가지·위기 후속 부탁)에 손을 보탠 것도 "상대한 날"**이다 (`q.helpers`). 무리의 일만 열심히 한 사람의
   개인 신뢰가 식으면, 무리의 일로 개인 신뢰가 깎이는 것과 같아지므로.
2. **대화로는 40까지만**: 무전 대화의 +1 은 신뢰 40 미만일 때만 (말로는 경계를 푸는 데까지, 그 위는 행동으로).

**개인 모드의 집단 신뢰 점검 (2026-10-09)**
- 집단 신뢰를 조건으로 쓰는 곳: 카운티 회의 결말(살아 있는 NPC 평균 50, 세 조건 중 둘), AI 곁가지 등급(25마다 1등급),
  디렉터가 청할 NPC 가중치, 관계 파급 하한(20), 후임(절반). 곁가지 62개·큰 이야기에는 신뢰 조건이 없다. 실제로 걸리는 곳은 회의 하나.
- 1~5장을 좋은 쪽 길로 따라갈 때 오르는 양 (이야기 부탁 +등급, 위기 +2): 레이 +24, 케이시 +19, 닥 +26, 파이크 +18, 듀이 +27,
  휘태커 +30, 빅 +25, 행크 +24, 곁가지 부탁 등급 합 NPC 마다 +3~7. 시작 평균 약 17 → 다 성공해도 회의(5장, 약 110~120일째) 때
  평균 약 46, 위기 외면(-2)·실패가 섞이면 35~45.
- 그래서 **장기 프로젝트 완성에 집단 신뢰 +15** (5-1절). 회의 전까지 8명 중 4명 완성이면 평균 +7.5 → 대체로 잘 따라온 무리는 50 근처.
  회의 조건(50)은 그대로 둔다. 구현 뒤 실제 진행으로 다시 센다.
- 개인 신뢰: 지금 신뢰도는 이야기 부탁에서 많이 오르는데 이 몫이 빠진다. 개인별 부탁(2~5일에 하나)·거래·지원·일거리·대화만으로
  한 사람이 40/60/80 에 닿는 데 며칠 걸리는지 구현 때 센다.

## 7. AI 말투

- **집단 신뢰 = 플레이어들(무리)에 대한 태도**, **개인 신뢰 = 지금 말하는 이 사람에 대한 태도**로 둘을 따로 넘긴다.
  - 1:1 답장: "Toward the players as a group you are ... (집단). Toward Gerald himself ... (개인)".
  - 이 사람을 얼마나 아는가 (`known`): 개인 신뢰 60 이상 = 잘 앎(well), "NPC 처음 값 + 10" 이상 = 조금 앎(little), 그 밖 = 거의 모름(new).
  - 무리는 믿지만 처음 보는 사람에게는 정중하되 조심스럽게, 혼자 많이 도운 사람에게는 무리보다 더 따뜻하게(집단이 낮아도).
  - 신뢰 때문에 거래를 거절하면 "너는 아직 잘 모른다" 식으로.
- NPC 가 먼저 거는 말(이야기·위기·방송·공용 주파수 장면)은 집단 신뢰만. 대상이 있는 반응(부탁 결과 반응·특기 무전)은 둘 다.
- 말투 수준(존댓말·반말 등)은 지금처럼 NPC 마다 고정이고 신뢰로 바뀌지 않는다.
- 싱글·공유 모드에서는 지금처럼 신뢰 하나만 넘긴다.
- 브릿지: `build_radio`에 `personal = { name, trust, known }` 추가, 태도 문구를 "무리"와 "이 사람"으로 나눠 씀
  → **브릿지 릴리스 필요**. 예전 브릿지는 personal 을 무시하고 지금처럼 말한다.

## 8. 어느 주파수로 오나 (2026-10-09 사용자 결정 B + C)

**지금**: 모든 부탁(디렉터 일반 부탁·이야기·곁가지·위기 호소)은 그 NPC 의 주파수로 온다(`Radio.react(fid, "request" | "crisis", ...)`).
그 주파수는 1:1 이 아니라 채널마다 기록이 서버에 하나라 모든 접속자에게 똑같이 보인다(`radioMessage` 전체 방송).
공용 주파수(121.5)에는 부탁이 없고 장면·소식·시장 제안만.

**개인 모드**
- **B. 개인별 부탁은 받은 사람에게만 보인다**: 같은 NPC 주파수 안에서 개인별 부탁과 그 결과 반응 줄(수락·완료·실패 무전)에
  `to = 받은 사람 키`를 달고, 서버는 그 줄을 받은 사람에게만 보낸다(`channelList`·채널 기록 보내기도 걸러서). 다른 사람에게는
  시스템 줄 하나 "레이가 ○○에게 따로 연락했다"(`private = true`, 내용 없음). NPC 의 기억(AI 기록·`ch.memory`)은 하나 그대로라
  NPC 는 누구에게 무엇을 부탁했는지 안다 (다른 사람과 이야기하다 언급할 수 있다 — 함께 하는 무리라 자연스럽다).
  받은 사람이 그 부탁에 대해 무전으로 말한 줄도 받은 사람에게만. 도운 사람은 퀘스트 탭에서 내용을 본다(퀘스트는 모두에게 보임).
  일지 교신 기록(`Radio.logLine` → `ps.radioLog`)도 이 줄은 받은 사람에게만 남긴다. 저녁 라디오 방송이 끝난 부탁을 소식으로
  다루는 것("○○가 레이의 부탁을 해냈다")은 그대로 둔다.
- **C. 무리의 부탁은 공용 주파수에도 알린다**: 큰 이야기·곁가지·AI 곁가지 부탁, 위기는 지금처럼 그 NPC 주파수로 오고,
  공용 주파수에 시스템 줄 "레이가 무리에게 도움을 청했다 (퀘스트 탭)", 위기는 "레이·닥·빅이 서로 다른 도움을 청했다".
  다음 공용 주파수 장면의 화제로도 넣는다(`Social.queueTopic`).
- 싱글·공유 모드는 지금 그대로.

## 9. 화면

- **싱글·공유 모드**: 지금처럼 신뢰 하나만 보인다.
- **개인 모드**: 교신 상태 줄·거점 탭·인물 탭·거래 목록·특기 아이콘에 크게 "내 신뢰 35", 작게 "무리 60". 혜택은 내 신뢰로 정한다는 툴팁.
- 무전 기록의 신뢰도 줄: 집단 변화는 지금처럼 모두에게, 개인 변화는 본인에게만 짧게 ("내 신뢰 +2").
- 퀘스트 상세: 무리의 일에는 "무리의 신뢰", 개인의 일에는 "내 신뢰"로 결과가 어디에 들어가는지 한 줄.
  개인별 부탁은 "○○ 앞으로 온 부탁", 받은 사람이 아니면 수락·거절 버튼 대신 "도우면 신뢰 x0.5" 안내.
- 퀘스트 탭: 사람이 많으면 남의 개인별 부탁이 쌓이므로 "다른 사람 부탁" 묶음으로 따로 (지금 묶음 5개 옆, 기본은 접힘).
- 인물 탭 "지나온 일"의 신뢰 20/40/60/80 처음 넘음은 집단 신뢰 기준 (무리의 이야기).
- 디버그: "개인 신뢰 조절"(교신 탭 상대, 요청한 사람 ±10·=값), 상태 줄 `personal ray: 이름=35 …`, "개인별 부탁 지금 받기".
- 서버 -> 클라이언트: `channelList`·`radioMessage`·`lifeList`·`tradeOptions`·`npcProfiles` 에 받는 사람의 개인 신뢰를 함께.
