# 설계 메모: 내 행동으로 NPC가 달라지는 느낌 (보류, 2026-09-28)

사용자와 논의만 하고 **아직 구현하지 않은** 설계. 진행하기로 하면 이 문서를 출발점으로 삼는다.

## 문제

지금도 신뢰도·이야기 분기(`Stories.ARCS`)·위기 선택으로 NPC가 달라지지만, 대부분 신뢰도 숫자 한 줄과 말투로만 드러나
"내가 이 사람의 삶을 바꿨다"는 체감이 약하다. 필요한 것은
**보이는 상태 → 내 행동이 상태를 바꿈 → 바뀐 상태가 말과 게임 규칙 양쪽에 드러남**이라는 고리.

## 제안 1. NPC 생활 상태 (핵심, 추천)

- NPC마다 3~4개의 상태: 식량·물, 의약품, 안전(방어·탄약), 기분(사기). 세력마다 중요한 것이 다름
  (닥 = 의약품, 파이크 = 식량, 방위대 = 탄약).
- 변화: 시간이 지나며 조금씩 줄어듦(소비), 사건으로 크게 흔들림(열병 위기, 폭풍, 습격, 이야기 속 불행),
  **내가 준 물건으로 오름**(부탁 전달, 거래 대가, 위기 지원).
- 표시: 교신 탭에 상태 막대 또는 한 줄 설명 ("파이크: 식량 바닥, 사기 낮음").
- 규칙에 반영:
  - 말: 모든 무전 요청에 상태를 넣음 (굶주린 레이는 기운이 없고, 내가 준 콩으로 버틴 뒤엔 고마워함)
  - 부탁: 가장 부족한 상태에 맞춰 `Needs`에서 고름
  - 거래: 부족한 품목은 비싸지거나 안 팔고, 넉넉한 품목은 싸짐 (`Trade.context`에 배율)
  - A-Life 지원: 탄약이 바닥인 방위대는 인원이 줄어듦 (`ALife.SIZE`에 보정)

## 제안 2. 관계 파급 (추천)

- 누군가를 도우면 그와 친한 NPC는 조금 오르고, 사이가 나쁜 NPC는 조금 내려감
  (`Stories.RELATIONS`에 친밀·적대 값을 더해 사용. 예: 빅을 도움 → 레이 -1, 파이크 -1 / 닥을 도움 → 케이시 +1).
- 무전에 이유가 적힌 시스템 줄로 보여 줌 ("레이는 네가 빅과 거래한 걸 못마땅해한다 (-1)").
- 모두에게 좋은 사람일 수 없게 되어 선택에 무게가 생김.
- **골고루 올리기와의 균형 (2026-09-29 검토)**: 막는 게 아니라 느려지게 한다. 지금 `Stories.RELATIONS`의 사이 나쁜 관계는
  대부분 빅 패거리(rats)와 방위대(guard) 쪽이고, 나머지 여섯(레이·케이시·닥·파이크·듀이·행크)은 서로 우호적이라
  이들을 도우면 오히려 서로 조금씩 오름. 대가를 치르는 건 빅·방위대를 도울 때뿐.
  - 파급은 직접 변화보다 작게: ±1, 3등급 이상 완료·위기 선택 같은 큰 일에만 (평범한 거래·대화는 파급 없음)
  - 감점은 "적대" 관계에만, NPC당 한 주 최대 -2
  - 파급 감점으로는 거래 가능선(20) 아래로 안 떨어짐
  - 소문 시스템과 연결: 그 NPC가 소문을 들어야 파급 (빅과의 거래는 거점 근처 목격·위기 선택처럼 드러난 경우만) → "몰래 거래"가 가능해 여덟 명 모두 높이는 길이 남음

## 제안 3. 행적 기록 (추천)

- NPC마다 나와의 주요 사건 기록: 부탁을 들어줌·거절, 위기에서 편들어줌·외면, 흥정 중 모욕, 선물, 지원 요청, 오사.
- AI가 구체적인 과거를 들춰냄 ("지난번 항생제 가져다준 거 아직 기억해", "트럭 때 우릴 버렸잖아").
- 누적 행적으로 별명·평판 ("약 가져다주는 사람", "빅이랑 어울리는 놈").
- 교신 탭에 NPC별 "관계 기록" 타임라인.

## 제안 4. 결과가 세계에 남음 (가능성 검토 완료)

| 기능 | 가능 여부 | 근거 / 확인할 것 |
|---|---|---|
| 무전 NPC의 죽음·떠남 (채널 잡음, 거래·지원·연락 끊김, 다른 NPC 애도) | 확실 | 게임 규칙 쪽. 모든 모듈이 "살아 있는 NPC만" 보도록 한 곳(`Social.alive(fid)` 같은 도우미)에서 걸러야 해서 손볼 곳이 많음 |
| 거점에 남긴 물건 (친하면 선물 상자, 떠났으면 남은 씨앗) | 확실 | 보급 퀘스트의 건물 찾기·보관함 배치·`setExplored`·강조를 거점 위치로 |
| 쪽지 (떠난 레이의 편지) | 가능 | 모드 전용 "쪽지" 아이템(modData에 글) + 우클릭 "읽기" 창이 확실. 바닐라 종이·노트에 글 쓰기는 B42 확인 필요. 글은 AI가 NPC 말투로 |
| 거점 모습 변화 (부서진 문, 털린 창고, 핏자국, 시체) | 대체로 가능 | 창문 깨기, 바리케이드(`IsoBarricade.AddBarricadeToObject`), 핏자국, `createRandomDeadBody` 등 바닐라 함수 있음. 서버에서 바꾼 것이 멀티 클라이언트에 보이는 동기화는 함수마다 확인 필요 |
| 거점 좌표 검증 | 먼저 필요 | `Factions.lua`의 8개 좌표는 "마을 근처" 수준. 농가·교회·정비소·오두막 같은 알맞은 실제 건물로 맞춰야 함 |
| NPC 본인이 거점에 서 있음 | A-Life 있을 때만 | A-Life 우호 NPC 한 명 스폰 + `hold` 명령. 외모는 A-Life 프로필에서 골라 설정과 똑같지 않음 |
| A-Life 세계 반영 (빅 패거리가 커지면 약탈단 출몰, 방위대가 검문소를 되찾으면 순찰) | 가능 | 우리 `ALife.spawnSquad`로 그 지역에 주기적으로 무리. A-Life 자체 출현 빈도 조작은 비권장 |

한계: 거점이 로드돼 있을 때만 바꿀 수 있음 → "해야 할 변화"를 기록해 두고 칸이 로드될 때 적용(보급품 배치와 같은 방식).
한 번 바뀐 거점은 세이브에 남아 되돌리기 어려움 → 테스트는 별도 세이브로.

진행 순서 제안: ① NPC 죽음·떠남 ② 거점 좌표를 실제 건물로 ③ 거점 선물 상자·쪽지 ④ 거점 모습 변화 ⑤ A-Life로 거점 NPC·세계 반영.

### A-Life 없는 거점 (검토, 2026-09-29)

B42 바닐라에는 사람 NPC가 없어 **걸어 다니는 NPC 본인**만 빼면 거점은 이 모드만으로 만들 수 있다.

| 요소 | 방법 | 근거 |
|---|---|---|
| 거점 건물·지도 표시 | NPC마다 실제 건물 지정, 지도 마커, 가까이 가면 방문 감지 | 보급 퀘스트 건물 찾기, `QuestMap` |
| 사람이 사는 흔적 | 전문 물품 보관함, 바리케이드, 레이의 밭, 듀이 정비소의 수리 중인 차, 핏자국 | 보관함 배치·`setExplored` 사용 중, 바리케이드·차량 함수는 바닐라에 있음 |
| 상태가 눈에 보임 | 생활 상태(제안 1)를 거점에 반영: 식량 바닥 → 창고가 빔, 습격 → 부서진 문 | 칸 로드 시 적용(보급과 같은 방식) |
| 대면 대화 | 거점 문 앞 우클릭 "○○와 이야기" → 교신 탭 대면 모드, AI에 "직접 만남" 전달 | 교신 흐름 재사용, 프롬프트 한 줄 |
| 직접 주고받기 | 거점 교환 상자에 넣으면 제출·대가 지불로 인정, 선물도 그 상자에 | 제출 검증·보관함 배치 재사용 |
| 쪽지·선물 상자 | 떠난 NPC의 편지, 친해지면 남기는 선물 | 위 표 |

NPC 본인을 보여 주는 방법:
1. **문 너머 목소리 (추천)**: 거점 문은 잠겨 있고 문 앞에서 말을 걸면 안에서 대답. 신뢰도가 높으면 "들어와" → 문을 열어 주고 안에는 생활 흔적. 몸이 없으니 죽음·동기화 문제 없음, 경계하는 생존자 분위기에도 맞음.
2. **옷 입힌 마네킹**: 서버에서 생성 가능 확인(바닐라 `server/ClientCommands.lua` 712행 `IsoMannequin.new`). 움직이지 않아 마네킹처럼 보일 수 있음. 캐릭터가 아니라 `Say`를 못 써서 말풍선은 클라이언트가 화면에 직접 그려야 함.
3. **좀비 기반 자체 NPC**: A-Life 방식(좀비 셸). 사실상 A-Life를 다시 만드는 일이라 비추천.

비교: 다른 모드가 필요 없고, 거점 NPC 죽음 문제가 없어 "대역" 규칙이 필요 없으며, 멀티 동기화가 단순함. 대신 움직이는 사람은 없음.
추천 조합: **기본은 이 모드만의 거점**(흔적·문 너머 대화·교환 상자·상태 반영), **A-Life가 있으면 대역 NPC를 추가로**(아래 결정 그대로).
확인 필요: 서버에서 잠근 문·바리케이드가 멀티 클라이언트에 보이는지, 세이브에 남는 거점 변화 관리, 마네킹을 쓴다면 옷 입히기·멀티 표시.

### 결정: 거점 NPC는 "대역" (사용자 우려 반영)

A-Life NPC는 좀비 어그로를 잘 끌어 쉽게 죽는다. 거점 몸이 죽을 때 무전 NPC까지 죽으면 난이도가 운에 좌우되므로 **묶지 않는다.**

- 무전 속 NPC(이야기·신뢰도·거래·지원)가 본체. 거점의 A-Life NPC는 방문했을 때 보이는 겉모습.
- 거점 NPC가 죽어도 무전 NPC는 살아 있음 → "다쳐서 몸을 피함"으로 처리: 무전 반응("좀비가 몰려와 도망쳤어, 너 거기 있었지?"),
  소문으로 전파, 며칠 뒤 방문하면 다시 있음. 신뢰도·이야기에는 영향 없거나 "네 덕에 살았다 / 날 두고 갔다" 정도의 가벼운 반응.
- 죽을 일 자체를 줄임: 플레이어가 거점 가까이(예: 40타일) 오면 나타나고 멀어지면 사라짐, 건물 안에서 `hold`,
  주변 좀비가 많으면 아예 나타나지 않음.
- 일부러 쏜 경우만 따로: 오사는 기존 보호(`ALife.installGuards`)로 넘기고, 반복 공격은 "네가 나를 쐈다"며 신뢰도 크게 하락.
- **무전 NPC의 진짜 죽음·떠남은 이야기 분기로만** (예: 케이시 아버지 사망, 레이가 루이빌로 떠남, 교회 붕괴).
  전투나 운으로는 일어나지 않음. 샌드박스 "NPC가 이야기에서 죽거나 떠날 수 있음"으로 끌 수 있게 하고, 끄면 최악의 결말도
  "크게 다쳤지만 살아 있음"으로.

## 남은 결정 (진행할 때)

1. 무엇부터 할지 (추천: 1 + 2 + 3)
2. 상태를 숫자·막대로 보여 줄지, 글로만 보여 줄지
3. NPC가 이야기에서 죽거나 떠날 수 있게 할지 (기본값)
4. 거점 방문(실제 장소 변화)을 넣을지
