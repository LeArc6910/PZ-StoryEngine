# 설계 메모: 여러 날 이어지는 큰 사건 (보류, 2026-09-30)

사용자와 정리한 아이디어. **아직 구현하지 않았다.** 진행하기로 하면 이 문서를 출발점으로 삼는다.
같은 날 나온 다른 후보는 `docs/IDEAS_NEXT.md` 끝의 "다음 후보 (두 번째)" 참고.

## 목표

지금 사건은 대부분 한 번에 끝난다(부탁 하나, 위기 선택 하나, 헬기 한 번). 큰 사건은 **3~5일에 걸쳐 단계별로 커지고**,
여러 NPC와 플레이어가 함께 대응하며, 결과가 세계에 오래 남는 이야기다. "그 주에 무슨 일이 있었지"로 기억되는 장(章)을 만든다.

## 기본 구조: 사건 = 단계들의 연결

```
[전조] ──(하루)──> [발생] ──(1~2일)──> [고비] ──> [결말: 성공 / 부분 성공 / 실패]
```

| 단계 | 하는 일 | 쓰는 기존 기능 |
|---|---|---|
| 전조 | NPC들이 이상한 낌새를 무전·공용 주파수에서 이야기, 라디오 방송에 한 줄 | 공용 주파수 장면 화제(`Social.queueTopic`), 소문(`Social.news`), 라디오 방송(`Broadcast`) |
| 발생 | 사건이 실제로 시작되고 관련 NPC들이 도움을 청함, 여러 퀘스트가 동시에 열림 | 부탁·소탕·보급 퀘스트(`Quests`), 위기 선택(`choice`) |
| 고비 | 가장 위험한 순간. 추적 무리나 A-Life 무장 무리가 실제로 들이닥침 | 추적 무리(`Hunt`), A-Life 습격·지원(`ALife`), 폭풍 |
| 결말 | 해낸 퀘스트 수로 판정. NPC 형편·관계·운명이 바뀌고 모두의 일지·방송·편지에 남음 | 생활 상태(`Life`), 관계(`Bonds`), 운명(`Fate`), 편지(`Letters`), 일지 |

- 단계는 시간이 지나면 넘어가고, 핵심 퀘스트를 일찍 끝내면 그 단계가 빨리 끝나거나 다음 단계가 약해진다. 무시하면 그대로 커진다.
- 판정은 전부 Lua. AI는 각 단계의 무전·장면·방송·편지에 서사만 입힌다 (관측·기록 계층 원칙 그대로).

## 사건 예시

### ① 군 헬기 추락 (방위대·빅·닥)

| 단계 | 내용 |
|---|---|
| 전조 | 케이시가 "군 주파수에서 조난 신호가 들렸다"고 알림, 방위대가 긴장 |
| 발생 | 카운티 어딘가에 추락 현장(보급 퀘스트 위치 선정 재사용). 현장 상자에 군 보급품(총·탄약·의약품)과 봉인된 서류. 방위대는 서류 회수, 빅은 "물자를 먼저 챙겨 오면 나눠 주겠다", 닥은 "생존자가 있을지 모른다"며 의약품 부탁. 누구를 우선할지 위기 선택 |
| 고비 | 소리를 듣고 현장에 대규모 추적 무리. A-Life가 있으면 빅 패거리 무장 무리도 현장으로 |
| 결말 | 서류를 방위대에 → 방위대 관계 +, 검문소 프로젝트 점수 + / 빅에게 물자 → 빅 형편 대폭 +, 방위대가 빅을 더 싫어함 / 아무것도 못 함 → 두 세력 충돌이 잦아짐 |

### ② 대이동 — 호드가 카운티를 가로지름 (레이·파이크·케이시)

| 단계 | 내용 |
|---|---|
| 전조 | 행크가 "북쪽에서 짐승들이 전부 남쪽으로 내려온다"고 경고, 라디오 방송에 이동 경로 예측 |
| 발생 | 이동 경로 위 NPC 거점(레이 농가, 파이크 교회)의 무기(안전) 자원이 매일 깎임. 두 곳 모두 바리케이드 자재·탄약 부탁 |
| 고비 | 플레이어 근처를 지나가는 대규모 추적 무리(진행 단계별 크기의 2배). 케이시가 정찰 표시로 무리 위치를 지도에 계속 찍어 줌 |
| 결말 | 지켜 낸 거점은 기호품(사기) +, 못 지킨 거점은 무기 바닥 → 교회 습격 위기나 NPC 떠남으로 이어질 수 있음 |

### ③ 열병 유행 (닥·파이크·듀이)

| 단계 | 내용 |
|---|---|
| 전조 | 파이크가 "피난민 중에 기침하는 사람이 늘었다" |
| 발생 | 매일 무작위 NPC 1~2명의 의약품·기호품이 떨어짐. 닥이 항생제를 모아 달라고 전체에 요청 (여러 사람이 나눠 내는 모금형 퀘스트) |
| 고비 | 닥 본인이 쓰러짐: 닥의 무전이 한동안 끊기고 치료 특기를 못 씀 |
| 결말 | 모은 양에 따라 NPC들 회복, 닥 형편 회복. 실패하면 한 명이 죽을 수 있음 (NPC 죽음·떠남 옵션이 켜졌을 때만) |

## 새로 필요한 것

| 구성 | 설명 |
|---|---|
| `server/StoryEngine/Events.lua` + 사건 데이터 | `Stories.ARCS`처럼 데이터로 정의: 단계, 기간, 관련 NPC, 단계별 퀘스트·호드·자원 변화, 결말 조건 |
| 사건 퀘스트 묶음 | 한 사건 안의 여러 퀘스트에 사건 ID를 붙여 진행도 합산, 퀘스트 목록 [사건] 표시 |
| 모금형 퀘스트 | 여러 플레이어가 조금씩 나눠 내는 부탁 (③). 지금 부탁은 한 번에 다 내야 해서 새로 필요 |
| 사건 탭 또는 목록 상단 표시 | "군 헬기 추락 — 2일째 / 고비까지 약 하루"처럼 지금 상황 |
| 디렉터 연결 | 디렉터 AI가 사건을 고르고, 사건 중에는 다른 큰 이벤트를 쉼 |
| 브릿지 | 새 모듈 없이 지금 모듈(무전·공용 주파수·방송·편지)에 사건 맥락 한 줄 추가 |

## 빈도와 멀티플레이

- 서버 전체로 **2~3주에 한 번**, 동시에 하나만. 첫 사건은 초반 이후(서버 경과 20~30일)부터.
- 진행 단계(초·중·후반)에 따라 호드 규모와 보상 등급이 커진다.
- 멀티: 모든 플레이어가 같은 사건을 공유하고 여러 퀘스트를 나눠 맡는다 (지금의 퀘스트 공유 규칙 그대로).
- 접속자가 없으면 사건 시간도 멈춘다 (다른 기능과 같은 방식).

## 위험과 주의점

- 작업량이 지금까지 기능 중 가장 크다 (데이터·판정·UI·테스트까지 장기 프로젝트의 2~3배).
- 위기 선택·급한 부탁·협박과 한꺼번에 몰리지 않게 사건 중에는 다른 NPC 요청 관문을 줄여야 한다.
- 고비 단계의 호드·무장 무리가 초반 플레이어에게 너무 셀 수 있어 진행 단계별 크기 표가 필요하다.
- 여러 날에 걸친 흐름이라 디버그 "사건 다음 단계로"가 있어야 인게임 테스트가 된다.

## 작게 시작한다면

사건 하나(① 군 헬기 추락)만, 퀘스트는 기존 종류로만, 모금형 퀘스트와 사건 탭 없이.
퀘스트 목록 [사건] 표시와 공용 주파수·방송 안내만 두면 장기 프로젝트 정도의 작업량. 반응이 좋으면 ②·③을 데이터로 추가한다.

# 전력·수도 복구 작전 (보류, 2026-10-01 사용자와 정리)

바닐라 단전·단수 뒤 플레이어와 NPC들이 함께 카운티의 수도·전기를 되살리는 **긴 임무**. 위의 큰 사건 틀(`Events.lua`)을 쓰는 첫 사건 후보.
**아직 구현하지 않았다.** 사용자가 정한 것은 "사용자 결정"으로 표시.

## 기술 확인 (2026-10-01, jar 바이트코드·바닐라 Lua)

- B42에는 전기·수도를 켜는 스위치가 없고, 매번 **샌드박스 값으로 계산**한다.
  - 전기: `SandboxOptions.doesPowerGridExist()` = 월드 경과 일수 < `ElecShutModifier`. `AmbientStreamManager.updatePowerSupply`가 그 결과로 `IsoWorld.setHydroPowerOn`을 부르고 `checkHaveElectricity`로 칸들을 갱신
  - 수도: `IsoObject.isWaterInfinite()`가 물을 쓸 때마다 `GameTime.getWorldAgeDaysSinceBegin()`과 `WaterShutModifier`를 비교
  - 바닐라 Lua의 판정식(`ISVehicleMenu`, `World.lua`도 같음): `worldAge/24 + (TimeSinceApo-1)*30 < ElecShutModifier`
- 그래서 **두 값을 "지금 경과 일수 + 60"으로 올리면 다시 켜진다.** 서버에서 `getSandboxOptions():set(이름, 값)` + `applySettings()` + `toLua()`
- 걸리는 점
  - 서버가 바꾼 샌드박스를 클라이언트에 보내는 Lua 함수가 없다. 바닐라는 관리자 클라이언트가 `sendToServer` → 서버 `receiveSandboxOptions`가 저장하고 모두에게 다시 보낼 때만 퍼진다 → **우리 명령으로 "복구, 값 N"을 보내 각 클라이언트가 같은 값을 직접 설정**, 새로 접속하는 사람은 접속 때 서버 값을 받음(확인 필요)
  - 호스트 재시작 시 서버 설정 파일(`Server/<이름>_SandboxVars.lua`) 값으로 돌아갈 수 있다 → 복구 상태(끝나는 날)를 ModData에 두고 서버 시작·접속 때마다 다시 적용 (`Tuning.apply`와 같은 방식)
  - 전등·냉장고가 바로 반응하는지, 다시 꺼질 때 바닐라 정전 소리(`WorldEventElectricityShutdown`)가 나는지는 인게임으로만 확인
- 전력망은 카운티 전체가 하나라 **마을별 복구는 안 되고 전체가 한꺼번에** 켜진다. 발전기는 영향 없음
- **본 작업 전에 디버그 "전기·수도 복구 테스트"로 싱글·멀티 호스트에서 위 세 가지를 먼저 확인**한다. 안 되면 "상징적 복구"(NPC 형편·이야기만)로 바꿔야 해서 재미가 크게 준다

## 시작 조건 (사용자 결정)

- 단전·단수가 **실제로 일어난 날부터 2주** 뒤부터, 하루 한 번 그날의 확률로 굴린다. 그날 확률은 **14일째 10%, 15일째 15%, 16일째 20% …처럼 하루 +5%**, 32일째 100%

  | 단전 뒤 날 | 14 | 15 | 16 | 17 | 18 | 19 | 20 | 21 | … | 32 |
  |---|---|---|---|---|---|---|---|---|---|---|
  | 그날 시작 확률 | 10% | 15% | 20% | 25% | 30% | 35% | 40% | 45% | … | 100% |
  | 그날까지 시작했을 확률 (참고) | 10% | 24% | 39% | 54% | 68% | 79% | 87% | 93% | … | 100% |

  - 아랫줄은 앞날들에서 이미 시작됐을 경우까지 합친 값이다. 대부분 단전 뒤 15~20일 사이에 시작된다
- 끊긴 날은 샌드박스 값으로 계산한다(`ElecShutModifier`·`WaterShutModifier` 날짜). 처음부터 꺼진 세이브(값 -1이나 이미 지난 날)도 그 날짜부터 센다 — `World.lua`가 "조용히 넘김"으로 처리한 세이브도 복구 임무는 나온다
- 수도·전력은 따로 굴린다. **동시에 하나만** 진행하고, 다른 쪽이 당첨되면 지금 임무가 끝난 뒤 바로 시작
- 접속자가 없으면 굴리지 않는다 (다른 기능과 같음). 서버 경과 일수가 너무 이르면(초반 30일 안) 보통 단전 전이라 자연히 안 나옴

## 복구 유지 (사용자 결정)

- 성공하면 **60일(2달)** 동안 유지: 그 값을 `지금 경과 일수 + 60`으로 설정
- 60일이 지나면 다시 끊기고(`World.lua`가 "전력망이 다시 무너졌다" 사건), **위 시작 조건이 처음부터 다시** 돌아 2주 뒤부터 다시 복구 임무
- 남은 기간은 퀘스트 탭 작전 표시와 라디오 방송("전기는 앞으로 약 N일")에 나옴. 끝나기 5일 전쯤 NPC들이 불안해하는 장면
- 유지 기간은 나중에 샌드박스 값으로 뺄 수 있다 (기본 60)

## 장소: 실제 시설 좌표를 쓸 수 있는가

- **좌표를 알면 그 장소에서 진행할 수 있다.** 지금 퀘스트는 등급 거리 안의 건물을 골라 쓰는데, 작전은 고정 장소 목록(`{ 이름, x, y, 종류 }`)을 주고
  가장 가까운 건물(물건을 놓는 퀘스트)이나 그 좌표 주변(소탕·방어)을 쓰면 된다
- 바닐라 지도 확인 결과 (2026-10-01, `media/maps/Muldraugh, KY/*.lotheader` 방 이름·타일 이름):
  - **이름이 붙은 발전소·변전소·정수장은 없다.** "power" 방은 병원 안의 작은 전기실(48_14, 50_7 셀), "electricroom"은 1x3 칸, "waterstorage"는 집 안 방
  - 실제로 있는 것: **송전탑**(`electricity_pylon`, 144개 셀 — 카운티를 가로지르는 송전선), **급수탑**(`water_tank`, 37개 셀), 공장·산업 부지(`industry_*`, "factory" 방), 라디오 탑(`radio_tower`)
  - 지도 라벨(`worldmap-annotations.lua`)에도 전력·상수 시설은 없다. 바닐라 비상 방송에 "Knox Power Grid" 문구만 있음
- 그래서 장소는 **실제 지형지물에 이름을 붙이는** 방식:
  - 수도: 급수탑(마을마다 하나쯤) = "○○ 급수탑", 큰 마을의 공장 부지 = "정수장"
  - 전력: 송전탑이 몰린 지점 = "송전선 중계 지점", 공장·산업 부지 = "변전소", 라디오 탑·관공서 = "제어소"
- 정확한 좌표 얻는 방법: ① `.lotpack`(칸별 타일 데이터)을 읽어 송전탑·급수탑 칸 좌표를 뽑는 스크립트, ② 게임 안 디버그 "주변 시설 찾기"(로드된 칸에서 타일 이름으로 검색해 로그), ③ 사용자가 디버그 좌표로 직접 찍어 알려 줌. ①이 한 번에 전부 얻을 수 있어 가장 낫다
- 좌표 목록이 생기면 작전은 **플레이어 위치와 무관하게 정해진 시설**로 가게 된다. 멀리 있는 마을이 포함되므로 "여러 도시를 돌며" 진행

## 구성

두 작전은 **같은 난이도**(2026-10-01 사용자 결정): 둘 다 약 12~14일, 5막, 여러 마을을 돌고, 4막 방어가 가장 어렵다.

## NPC 지원 — 특기 대기 시간과 무관

작전 중에는 막마다 정해진 NPC가 **상황을 보고 스스로** 특기를 쓴다. 평소 특기 대기 시간에 걸리지 않고 소모하지도 않는다.
자원 비용은 없거나 절반. 신뢰도가 높을수록 구간이 커지고, 낮아도 구간 1로는 돕는다 (물·전기는 모두에게 필요하므로).

| NPC | 작전 중 지원 | 언제 |
|---|---|---|
| 케이시 | 정찰 표시를 작전 내내 유지 (목표 주변 무리를 지도에 계속) | 전 막 |
| 방위대 | 저격 엄호, A-Life가 있으면 분대 | 소탕·방어 시작 |
| 행크 | 목표로 다가오는 무리 경보 + 저격 | 방어 중 접근할 때 |
| 빅 | 미끼 소음으로 무리를 다른 쪽으로 | 방어 웨이브 사이 |
| 닥 | 원격 치료 1회 | 막마다 크게 다쳤을 때 |
| 듀이 | 작전용 차량 수리 | 2막 시작 |
| 레이 | 식량·물 보급 | 각 막 시작 |
| 파이크 | 위로 (공포 없음·지루함 감소) | 방어 직후 |

- 죽거나 떠난 NPC는 돕지 못한다 → 그동안 NPC들을 지켜 온 만큼 작전이 쉬워진다
- 지원할 때마다 무전 + 머리 위 대사(특기 답장 표시 재사용), 공용 주파수·라디오 방송이 진행을 다룬다

## 난이도와 실패

- 막마다 기한. 넘기면 그 막 실패 → 되돌림(같은 막을 더 큰 무리로 다시, 또는 모금량 증가). 같은 막 두 번 실패면 작전 실패
- 작전이 실패하면 시작 조건이 다시 돈다 (2주 뒤 10%부터)
- 소탕·방어 무리는 진행 단계·샌드박스 배율(`HuntSizeMult`)을 따르고 일반 소탕의 1.5~2배
- 성공: 60일 복구 + 모든 NPC 기호품·식량 기준값 상승, 일지·방송·편지, 세계 변화 상태에서 "no power / no running water" 빠짐

## 멀티

- 모든 플레이어가 같은 작전 공유(지금 퀘스트 공유 규칙), 병렬 소탕은 나눠 맡기, 모금은 여럿이 조금씩
- 작전 중에는 다른 NPC 부탁·위기·협박 관문을 줄인다

## 새로 만들 것

| 구성 | 비고 |
|---|---|
| `Grid.lua` | 전기·수도 켜기(끝나는 날 저장), 클라이언트 동기화, 재시작·접속 때 다시 적용, 시작 확률 굴리기. **먼저 인게임 확인** |

| 큰 사건 틀 | 위 `Events.lua`(막·기한·진행도·되돌림). 다른 큰 사건도 재사용 |

| 브릿지 | 무전·장면·방송·편지에 작전 맥락 한 줄 |

## 권하는 순서

1. 디버그 "전기·수도 복구 테스트": 싱글·멀티 호스트에서 불·물이 들어오는지, 재시작 뒤 유지되는지, 클라이언트 동기화
2. `.lotpack`에서 시설 좌표 뽑기
3. 큰 사건 틀 + 모금형·방어형·병렬 소탕을 만들고, 먼저 끊긴 쪽(보통 수도와 전기는 따로 무작위 날짜) 작전으로 흐름 검증
4. 두 작전은 데이터만 다르므로 나머지 하나는 데이터 추가로 끝
